## Findings

The run stopped after `new-commit`: it found a product defect, reported before any fix.

- **Defect: on GitLab the cancelled job does not cancel its simulation.** GitLab cancelled job 1047407
  93 seconds after the new commit (`WARNING: script canceled externally (UI, API)`). The signal killed
  the child `sf project deploy start` first: `deploy:smart` saw the command fail ("Sadly there has been
  Deployment error(s)", 03:30:43), and its catch block ran `deployJobIdWatcher.stop()`, which deletes
  `.cache/sfdx-hardis/running-deployment-simulation.json`. The process then exited with code 130
  (`ExitError: EEXIT: 130`, SIGINT handler of sf-plugins-core). When the `after_script` ran,
  `sf hardis:project:deploy:cancel` printed "No running deployment simulation found for this CI job:
  nothing to cancel", and DeployRequest 0AfEc00000qAKkIKAW stayed `InProgress` until it ran all its
  tests. On GitHub the same flow worked (the step `if: cancelled()` found the file).
- **The after_script path itself works**: it ran in a new container, saw `CI_JOB_STATUS=canceled`, the
  build of the branch was linked again from the builds volume, `sf hardis:auth:login` logged in again,
  and `deploy:cancel` ran. The `!E2E after_script: no build` part of `NC-GITLAB-AFTER-SCRIPT` is a
  scenario bug (GitLab echoes the command text, which holds that string), fixed since.
- **CI_JOB_STATUS is `failed`** in the after_script of a job that failed (the first attempt, ENOSPC on
  the runner): nothing is cancelled then, as expected.
